Stickman Studio Master Guide

A local-first, high-throughput desktop video production suite engineered for 2D stickman documentary storytelling. Stickman Studio orchestrates multi-agent Chrome workers, automated Meta.ai browser bridging, 3-tier image fidelity QA, and sub-frame audio synchronization into broadcast-grade 1080p MP4 master videos.

01

System Overview & Core Philosophy

Traditional AI video creation requires constant copy-pasting into web interfaces, messy download directories, manual file renaming, and slow video editing in Premiere or CapCut. Stickman Studio solves this entirely on local Windows hardware by introducing a dedicated six-stage production engine:

⚡
Local-First Desktop Engine
Zero cloud lock-in. Powered by SQLite in WAL (Write-Ahead Logging) mode, Express REST API, and native Windows binaries (FFmpeg & FFprobe).
🤖
Multi-Worker Chrome Farm
Orchestrates parallel isolated Chrome instances (W01–W08) with dedicated profiles, avoiding session conflicts and cross-talk on Meta.ai.
🛡️
3-Tier Fidelity QA
Every generated image is validated for magic byte signatures, exact resolution, forbidden photorealism tokens, and script adherence before ingestion.
🎬
Interactive Canvas Player
Hardware-accelerated HTML5 canvas player with live Ken Burns smooth zoom & pan, audio waveform scrubbing, and real-time scene director controls.

Step 2: Chrome Worker Farm & Extension Bridge

Meta.ai enforces strict anti-abuse and session limits. To bypass rate-limits and enable high concurrency, Stickman Studio manages up to 8 independent Chrome profiles:

Workers Profile Layout: E:/stickman-video-automation/Workers/ ├── Worker-W01/ (User Data Profile 1 + Extension Bridge) ├── Worker-W02/ (User Data Profile 2 + Extension Bridge) ├── Worker-W03/ (User Data Profile 3 + Extension Bridge) └── Worker-W04/ (User Data Profile 4 + Extension Bridge)

Worker Lease & Heartbeat Protocol

Each worker communicates with the local REST API via periodic heartbeats. When a worker requests a job:

  • Backend locks the prompt with a 120-second lease to prevent double-generation.
  • Worker side panel types the prompt into Meta.ai chat interface and listens for image generation.
  • Once generated, the worker clicks the image download button and sends a heartbeat report to the backend.
  • If a worker crashes or fails to report a heartbeat within 30 seconds, the orchestrator revokes the lease and reassigns the prompt to another idle worker.
⚠️ RAM Telemetry & System Throttling
Running 4 Chrome profiles concurrently consumes approximately 3.5GB to 5.5GB of physical RAM. Monitor the live RAM Telemetry Bar in Step 2. If memory exceeds 85%, close unused background applications or reduce active workers to 2.

Step 3: Central Media Ingestion & Visual QA

Downloaded images cannot be used directly from browser temp folders. The Ingestion Engine performs automated reconciliation:

1. Signature Validation
Reads the initial 64KB byte buffer of every downloaded file. Verifies exact magic bytes for PNG (89 50 4E 47), JPEG (FF D8 FF), and WebP (RIFF...WEBP). Rejecting truncated or corrupt downloads.
2. SHA-256 Checksum & Dedup
Calculates cryptographic SHA-256 hash. Detects identical duplicate downloads or AI hallucination loops.
3. Centralized Asset Migration
Safely copies images into Projects/{project_id}/central_images/ with standardized sequential naming: 001_stickman.webp.

Interactive Visual QA Gallery

In Step 3, you can view the complete asset gallery. Click any thumbnail to open the HD Lightbox. If an image fails creative intent, click Replace Image to upload an alternative or trigger a re-roll without breaking timeline synchronization.

Step 6: AI API Keys Vault & 10-Worker Isolated Login Assistant

Stickman Studio V2 features an enterprise-grade API key vault and a robust 10-worker browser farm architecture. Every browser worker is strictly isolated to one extension and one service (either Meta AI or Google Flow).

1. Dedicated 1-Worker-1-Extension Architecture

Key Architectural Rule: Strict Single-Service Isolation

Dual tabs and dual extensions inside a single browser instance cause session conflicts, memory bloat, and cookie crossover. In Studio V2:

  • Flow Workers (W01, W03, W05, W07, W09 by default): Open strictly https://flow.google.com/?pli=1 and load only the Veo Flow Automation extension with isolated config (WORKER_ID: Wnn, PROVIDER: flow).

  • Provider Toggle: Any worker can be switched between Flow and Meta instantly with the ⇄ Switch button or POST /api/v1/workers/:id/provider.

To automate prompt generation across all 10 workers without continuous login re-prompts:

Comprehensive System Audit & Resolved Flaws

During the comprehensive system review, the following bottlenecks and edge-case flaws were detected and resolved:

✅ Resolved: Timeline Reorder Desync
Flaw: Reordering scenes or editing slide durations in the Scene Director only modified local browser memory without persisting to SQLite. Clicking render exported the video in the old sequence.
Fix: Implemented PUT /api/v1/projects/:id/timeline/sync and auto-debounced backend synchronization.
✅ Resolved: Aspect Ratio Support
Flaw: Render engine and FFprobe validation had hardcoded 1920x1080 resolution, causing vertical 9:16 renders to fail validation.
Fix: Parameterized aspect ratio (16:9 Landscape @ 1920x1080 vs 9:16 Vertical @ 1080x1920) across routes, FFmpeg filters, and probe validation.
✅ Resolved: WebP Image Demuxing
Flaw: Concat demuxer with WebP still frames required normalized forward-slash paths and proper framerate declarations.
Fix: Validated Windows path conversions and verified successful multi-image WebP concatenation.
⚠️ Memory Footprint in Multi-Worker Setups
Bottleneck: When 4+ Chrome profiles are active simultaneously, RAM usage can spike by 4GB–6GB. On systems with 16GB RAM, opening too many workers can cause minor disk paging.
Mitigation: Added RAM Telemetry indicator and memory warning badge when usage exceeds 85%.

Troubleshooting & Error Guide

Meta.ai Worker "Login Required" or Extension Not Responding

1. Launch the specific worker profile manually: node studio/launcher.js --worker=W01.
2. Log in with your Facebook/Meta account once in the browser window.
3. Pin the Stickman Studio Bridge extension and verify that the side panel opens without permission alerts.
4. Close the browser. Subsequent automated runs will preserve the logged-in session cookie.

FFmpeg Binary Missing Error

Stickman Studio expects precompiled Windows binaries at: E:/stickman-video-automation/studio/bin/ffmpeg.exe and ffprobe.exe. If you are moving the project to a new computer, copy the binaries into the studio/bin/ folder.

Orphaned or Missing Media Recovery

If images were manually copied or deleted from the project folder, open Step 6: Telemetry & Logs and click Reconcile Database & Files. The engine will scan all files on disk, update checksums in SQLite, and repair missing references automatically.
